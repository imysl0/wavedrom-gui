# wavedrom-gui × kodbox 插件

把 wavedrom-gui 波形编辑器装进 kodbox：**`.wave` / `.wave.svg` / `.wave.png` 三种文件可以直接新建、双击打开、编辑后写回原文件**，只读的文件给预览页。编辑核心就是仓库根的 `index.html`（一行未改），宿主能力全部在 `static/app/bridge.js`（编辑）与 `static/app/preview.js`（预览）里，与 [VSCode 插件](../vscode/README.md)、[wavedrom-render Skill](../SKILL/wavedrom-render/SKILL.md) 共用同一套图片元数据规格。

| 后缀 | 存的东西 | 打开时 | 保存时 |
| --- | --- | --- | --- |
| `.wave` | WaveJSON 文本 | 直接读进编辑器 | 按代码面板的格式（紧凑/舒缓）写回 |
| `.wave.svg` | SVG 图，`<metadata>` 内嵌 WaveJSON | 解出内嵌代码，画面原样显示 | 按**原导出风格**重绘 SVG 覆盖写回 |
| `.wave.png` | PNG 图，`iTXt` 块内嵌 WaveJSON | 解出内嵌代码，画面原样显示 | 按**原导出风格**重绘 PNG 覆盖写回 |

图片是「源」而不是产物：解码 → 编辑 → 重绘 → 覆盖，导出来源（官方渲染 / 编辑区矢量重建 / skill-modern）记录在元数据里，重绘时按同一条路走，所以反复编辑不会把风格洗掉，也不会把 PNG 转成有损的别的样式。新建的图片还没有元数据，默认按**编辑区（现代）风格**出图——与你在界面上看到的预览一致，与 VS Code 插件对无标记图片的兜底也同调；存下第一次之后就跟它自己的标记走了。

## 安装

**从 Release 装（推荐，无需源码）**：下载 `wavedrom-kodbox-plugin.zip`，解压到 kodbox 的 `plugins/` 目录——包里已带顶层 `wavedrom/` 目录和构建好的编辑器，解压完就是 `plugins/wavedrom/`。然后 kodbox 后台 → 插件中心 → 找到「波形图编辑器」→ 启用，已登录的标签页刷新一次生效。

**从源码装**（本目录即插件源码，`editor.html` 是不入库的构建产物，缺它时插件页面会提示执行这条命令）：

```bash
cd kodbox && node scripts/build.js --zip ../wavedrom-kodbox-plugin.zip   # 生成编辑器 + 发行包
#   只想要目录形态就省掉 --zip，然后把本目录整体拷到 kodbox 的 plugins/wavedrom
cp -r kodbox /path/to/kodbox/plugins/wavedrom
```

发版流水线（`.cnb.yml` 与 GitHub Actions）会跑同一条 `build.js --zip` 并把 zip 挂成 Release 附件。插件 `version` 在构建时对齐仓库 tag（`v260921.3` → `260921.3.0`，与 VS Code 扩展同号）：流水线用 `WDGUI_VERSION` 把本次 tag 显式传进去（浅克隆里 `git describe` 可能取不到 tag），本地构建则自动退回 `git describe`。

兼容 kodbox 1.6x（开发实测于 1.69.03），无数据库、无外部依赖、不改核心文件。

## 使用

- **新建**：文件列表工具栏「新建文件夹 ▸」或空白处右键 → 新建 → 时序图(源文件) / 时序图(SVG) / 时序图(PNG)。三种都先走核心的**行内改名**——默认名已按同级去重，就地改掉再回车即可，`Esc` 取消且不会留下文件。图片两种确认后落一个空文件，编辑器打开后立刻按起始图表渲染一次写回，于是新建出来的就是一张能看的波形图。
- **打开**：双击 `.wave` 直接进编辑器；`.wave.svg` / `.wave.png` 在默认「接管图片」开启时也走编辑器，**普通 `.png` / `.svg` 不受影响**，仍旧是图片查看器。没有写权限的文件双击进预览页（见下）。
- **右键「打开方式」→「波形图编辑」**：`.wave.png` / `.wave.svg` 的真实扩展名是 `png` / `svg`，核心按扩展名列候选，所以插件把这两个后缀也挂进自己的支持列表（排在末尾，不抢普通图片的默认打开）。右键菜单每次显示时再按**整个文件名**收一遍：`*.wave` / `*.wave.svg` / `*.wave.png` 才露出这两项，普通照片的「打开方式」里看不到。这项与「接管图片」无关，关掉接管时它就是唯一入口。
- **右键「打开方式」→「波形预览」**：同一条插件路由的第二个入口（`plugin/wavedrom/preview`），只看图、没有编辑外壳。可写的文件预览页右上角有「编辑」，点了原地切进编辑器；只读的文件按钮是灰的，点它会弹「只读：没有该文件的写入权限」。`.wave.png` / `.wave.svg` 摆的就是盘上那张图，`.wave` 源码没有现成的图，预览页会临时装一个编辑器渲一次 SVG 再取回来（所以第一次要等一下，见排错）。
- **保存**：顶栏「保存」或 `Ctrl+S`；状态位依次是 正在读取文件… → 有未保存的改动 → 正在保存… → 已保存。后台设置里打开「编辑后自动写回」则停手约 1 秒自动落盘。
- **左侧菜单「波形图」**：不带文件的独立编辑器。这时点「保存」弹的是核心自己的「文件保存到」对话框——选目录 + 一个**带全后缀的文件名**（默认 `波形图.wave.png`，改成 `.wave` / `.wave.svg` 就按那一种出图），落盘后这个编辑器就绑到了该文件，再 `Ctrl+S` 直接覆盖。没选文件之前，顶栏「导出」仍是下载到本地。
- **只读文件**（没有写权限）：双击进的就是预览页——插件的编辑器路由发现 `fileCanWrite` 为假时直接改出预览页，不再给一套用不上的编辑外壳；要主动看也从「打开方式 → 波形预览」进。外链进来、或从侧栏菜单打开的无文件编辑器，「保存」弹的是「文件保存到」，等于另存一份副本，不会去动原文件。

## 后台设置项

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 打开方式 | 内嵌 | 内嵌面板 / 弹窗 / 新窗口，与 kodbox 其它应用一致 |
| 接管 `.wave.png` / `.wave.svg` | 开 | 关：双击走系统默认（图片查看器），只能从「打开方式」进编辑器；新建菜单里也不再出现这两种图片 |
| 编辑后自动写回 | 关 | 开：停止编辑约 1 秒写回原文件 |
| 关联扩展名 | `wave` | 追加别的扩展名（如 `json`）让编辑器认领更多源码文件 |
| 优先级 | 120 | 多个应用关联同一扩展名时谁在前 |
| 权限 | 所有用户 | 谁能看到菜单和用这个编辑器 |

## 写回的安全边界

保存接口是插件自己的 `plugin/wavedrom/save`，kodbox 的全局 CSRF 过滤对插件路由是直接放行的，所以这里自己把了几道关：

- 路径先按核心的语义归一化（`{source:父ID}/文件名` → `{source:自身ID}/`），再交给 IO 层，越权与穿越在同一条解析里被挡掉；
- 写权限走 `explorer.auth.fileCanWrite`：只读用户点开编辑器路由时，插件直接改输出预览页（不给保存按钮），保存接口那边还会再校验一次同样的权限；
- 文件类型以**服务端解析出的真实文件名**为准，不信前端传来的 `name`，只认 `.wave` / `.wave.svg` / `.wave.png`；
- 内容与后缀必须相配：PNG 看 `89 50 4E 47` 文件签名，SVG 要求 `<svg` 标记，`.wave` 拒绝markup 并限 8 MB；
- `csrfProtect` 开启时校验 `CSRF_TOKEN`；cookie 被核心其它接口清掉时退回同源判断（比对 `Origin`/`Referer`），不放行跨站写。

## 排错

- 页面提示「缺少 static/app/editor.html」→ 没跑构建，见上面第 1 步。
- 双击 `.wave.png` 打开的是图片查看器 → 后台把「接管 `.wave.png` / `.wave.svg`」关了，或改完设置没刷新页面；这时可以从右键「打开方式」里手动选「波形图编辑」。
- 打开后提示「该文件里没有内嵌的波形数据」→ 这是一张普通图片改了名，或元数据被别的工具抹掉了；此时保存会用起始图表覆盖原内容，先取消。
- 状态卡在「正在保存…」或「保存失败」→ 看 kodbox 是否登录过期、目录是否只读、磁盘是否可写；错误详情走编辑器右下角提示。
- 改了插件文件但界面没变 → 后台刷新页面；`bridge.js` 的 URL 带版本号 + 文件 mtime，正常会自动失效，若套了 CDN 请一并刷新。
- 宿主侧文案（右键菜单、应用标题）不随语言切换 → 这些文案必须写成 `{{LNG['wavedrom.xxx']}}` 占位符，由宿主输出 `main.js` 时替换；不能在运行时查 `LNG['wavedrom.xxx']`——页面里的 `LNG` 表只并了核心自己的键，插件 `i18n/` 不会进去。编辑器界面内部的语言由 `app.php` 单独注入，不受这条限制。
- 图标不换 → nginx 对图片发的是 `max-age=30d`，所以图标 URL 必须带缓存串：`main.js` 里用 `{{package.version}}` 自动跟随，`package.json` 的 `source.icon` 由 `node scripts/build.js` 按 `version` 回写。`version` 本身又在构建时对齐仓库 tag，所以**换图标只管换文件、跑一次构建**，三处（版本号、图标缓存串、编辑器徽标）会一起跟上。
- 列表里 `.wave.png` / `.wave.svg` 没有预览图 → 是核心的封面缩略图没出：确认 `fileThumb` 插件开着、服务器有 GD/Imagick；`.wave` 源码文件本来就没有预览，显示的是波形图标。
- 「波形预览」里 `.wave` 转圈很久、最后显示的是源码文本 → 源码文件盘上没有图，预览页要临时装一次编辑器来渲 SVG（正常 1~2 秒，超过 20 秒算失败并回落到显示文件内容）。要看具体哪里出错就从「打开方式 → 波形图编辑」进编辑器；`.wave.png` / `.wave.svg` 的预览不经过这一步，秒开。
- 预览页的图看着还是旧的 → 图片 URL 的缓存串是文件的 `modifyTime`（nginx 对图片发 `max-age=30d`），同一秒内被覆盖过就可能命中旧图，刷新一次应用页即可。
- 中文文件名、多标签页同开一个文件都可用（每个文件一份独立的自动保存键，互不覆盖）。

## 已知限制

- 预览页只出图：不能缩放、不看代码面板。`.wave` 的预览按**编辑区（现代）风格**出图（源码文件没有「原图风格」可继承，与新建时的默认一致）。
- 预览页点「编辑」是在当前这一页里换成编辑器，kodbox 顶部标签的标题仍写着「波形预览」。

- 「另存为」绑定的文件只在当前这一页有效：刷新应用页会回到未关联文件的状态（图表本身还在，编辑器的自动保存会把它取回来），要继续写回原文件就从文件列表双击它。
- 后台「打开方式」选成**新窗口**时，编辑器是独立标签页、没有宿主页面，「另存为」弹不出来，保存按钮保持禁用——这时只能用顶栏「导出」下载到本地。
- 外链分享页里的编辑未做验证，请在登录态的文件列表里用。
- `.wave.png` 的写回是「重绘」，像素级结果取决于当前浏览器的字体与渲染，和原图不会逐字节相同。
- 编辑器界面语言跟随浏览器，与 kodbox 界面语言各自独立（顶栏地球按钮可切）。
